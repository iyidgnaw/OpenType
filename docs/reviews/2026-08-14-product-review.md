## 0. 结论

工程质量明显跑在产品清晰度前面。功能不缺——3 模式、provider 可配、Agent 有真工具、多轮续接、审计链都做完了。
缺的是一条主线：**「OpenType 到底替我省了什么，且别人做不到」**。

现在它同时是一个听写工具、一个语音问答、一个带 shell 的本地 Agent，而这三件事在任何一个维度上都不像同一个产品。

更要紧的是：CLAUDE.md 里写的愿景是 **context-aware speech-to-text correction**——用得越久识别越准。
这条线是真正的差异化，也是最便宜的，但目前一寸都没落地。

## 1. 四个结构性问题

### 1.1 三个模式其实是三个使用频率差 50 倍的产品

| 模式 | 频率 | 延迟预算 | 失败代价 |
|---|---|---|---|
| 听写 | 一天 50 次 | <1.5s | 低（重说） |
| 问答 | 一天几次 | 5–10s | 低 |
| Agent | 一天 1 次 | 30s+ | 高（真跑了命令） |

它们共用一个热键、一个模式选择器，代价是**用户必须在开口之前声明意图**。而「帮我查一下今天的汇率」到底是
问答还是 Agent？判据是「这需不需要调工具」——那是实现细节，用户没有义务知道。ask 和 agent 现在的产品分界线
就是 `filterToolSet` 里的两个工具名（`sidecar/src/oneshot/routes.ts`），这个界线用户感知不到。

**建议：3 模式 → 2，「输入」和「助理」。** ask/agent 合并成一个入口，工具集和迭代上限内部决定；先内联在卡片里
跑，超过 N 秒自动「脱手」转后台 + 通知（Agent 现在已经是这个行为，只是被提前固化成了一个用户要选的模式）。
用户要做的决策从三选一降到「这句话是要写字，还是要办事」。

### 1.2 记忆是叙事核心，但现在是空转的

核对下来：

- Swift 侧那一整层（`AgentMemoryStore.entriesForPrompt` / `LocalMemoryRetriever`）**零生产调用**
- sidecar 侧的 episodic 事件**只有 `/agent/run` 会写**，听写和问答都不进
- consolidation 的 `shouldConsolidate` gate **没有任何调用者**，只能手动点
- owner facts **全量注入**，不做相关性筛选
- 实体词典只读，唯一写入方式是对 Agent 说「记住…」

但真正致命的不是这些，是：**唯一能让用户在 3 秒内感知到「它记住了我」的那条路根本没接**。
`sidecar/whisper/serve.py:115` 调 `mlx_whisper.transcribe()` 只传了 `path_or_hf_repo`，没有 `initial_prompt`。
词典躺在 SQLite 里，识别的时候一次都没用上。

记忆现在只在低频路径（ask/agent）里生效，它应该在高频路径（听写）里生效。

### 1.3 纠错是这个产品最好的点子，但它被做成了全局开关，而且不产生复利

Review 是 `AppConfiguration.transcribeVariant`，一个全局 Settings 开关：要么**每次**都弹面板复核，要么**每次**
都不复核。而真实需求是——90% 的句子直接写入，10% 有专有名词的要看一眼。全局开关对这个分布无解，结果是绝大
多数人会关掉它，然后这个功能等于不存在。

而且纠错不产生复利。用户在面板里把「呸泡」改成「PayPal」，这次对了；下次还是错。USER_GUIDE 自己写的补救办法
是「改完之后再对 Agent 说一次『记住呸泡就是 PayPal』」——**没有人会做这一步**。

这三件事连起来才是产品：

1. **事后纠错窗口**：直接模式照常立刻写入，但刚交付的那段保持「热」N 秒，这段时间内按热键 = 「纠正刚才那句」，
   而不是开始新录音。把 Review 从全局开关变成事后可选。
2. **每次纠错自动入词典**——用户不需要再说「记住」，他改的动作本身就是标注。
3. **词典回灌 ASR**：高置信度词条拼成 `initial_prompt`（mlx-whisper 原生支持），加上转写后 alias→canonical 的
   确定性文本替换（这一步不需要 LLM）。

这就是「用得越久越准」，是留存钩子，是 OpenTypeless 明确没做的事，也是这批里投入产出比最高的。

### 1.4 Agent 的信任模型和语音这个输入通道不匹配

`opentype__bash` + 无沙箱 + 无确认 + `yoloApprovalPolicy` 永远 allow——这是明确的 owner 决定，不翻。但触发通道
是**准确率最低的语音**，而且转写出来的任务文本在执行前**不给用户看**。「删掉这个目录里的旧文件」被听错一个词，
用户是从 step log 里知道的。

不需要加沙箱。最小成本的两件事：

- 下发前把「我听到的任务」显示 1.5 秒，可撤销（顺带解决 ASR 误听的普遍问题）
- 破坏性命令（`rm`/`mv`/带重定向的 `sh -c`）走一次卡片确认——`ApprovalPolicy` 的 seam 已经在那儿了，接一个
  policy 就行，不用重构

## 2. UX：按用户旅程

### 首次

- ~~**分发是最大的漏斗**。现在的安装路径是「clone 仓库 + 自己搭 Python venv + 编译」，README 甚至建议把
  prompt 丢给自己的 coding agent 去跑。这意味着这个产品目前的用户数上限约等于 1。~~

  **这条在写下的当天就已经过时了，是本文最大的一处失准，留在这里而不是删掉。** 同一天（2026-08-14 中午，
  提交 `a15c175`…`0ec2eb0`）另一条线已经把分发做掉了：`curl -fsSL …/install | zsh` 一行安装，脚本自己拉
  release、装进 `/Applications`、装依赖、本机构建 Whisper 环境、重新签名，并且询问语音识别跑在本机还是远程。
  没有做 DMG，而且**不该做**——venv 记录创建它的解释器的绝对路径且不自带标准库，打进包里在别人机器上必然是
  死的，所以本机重建才是对的解法（也让归档从 ~1.2 GB 降到 ~74 MB）。

  教训不在于这条建议本身，而在于**我是在一个正在被并行修改的仓库里做的评审**，却按静态快照下了判断。
  产品评审给出的「最大漏斗」如果指向一个已经在修的地方，会直接误导排期。

- Whisper 模型仍然没有任何 UI，连 `OPENTYPE_WHISPER_MODEL` 在 Swift 侧都没接；安装脚本问的是「本机还是远程」，
  不是「用哪个模型」。默认 `whisper-small` 的中文专有名词错误率就是用户的第一印象——**这半条依然成立**，
  而且在 P0-1 落地之后更值得做：词典偏置能救回一部分专有名词，但救不回模型本身听不清的部分。

### 录音中

- 没有录音时长显示，也没有最长时长保护。双击进 hands-free 后忘了，就一直录。
- 浮层固定读 `NSScreen.main`（`OverlayController.swift:397`），多屏用户会看到它出现在错误的屏幕上。
- 左 Option 长按 0.3s 触发，但 Option+拖拽/点击不取消计时——按住 Option 拖文件就误触录音。
- 模式切换 chord 永远绑死左 Option+Shift/Tab，跟用户选的预设脱节；popover 里那行「按住时点 Shift 或 Tab」对
  fn / 双击用户是**错误指引**。

### 交付后

- 「转写语言」27 种语言只影响 Apple 的实时字幕预览，不影响最终识别——名不副实。`asr/routes.ts` 里连
  `language` 字段都不存在。
- 历史没有搜索、筛选、单条删除，`history.json` 100 条上限；也没有「重新粘贴上一条」的全局热键。
- **一个数字都没有**：没有耗时、没有字数、没有纠错率。既没有产品指标可以判断「是不是变好了」，也没有留存钩子。

### 长期

- UI 硬钉死中文（`InterfaceLanguage` 已删）。这是个明确的分发天花板。
- 菜单栏图标 `isTemplate = false` 的彩色方块违反 HIG，状态纯靠颜色编码，色觉障碍不可分辨。

### 一个值得单独决定的定位问题

「直接模式」现在的承诺是「一个字都不多、一个字都不少」，这是个清晰、诚实的定位。但对最高频场景（微信、笔记），
输出里带着「嗯」「那个」和改口。Wispr / superwhisper 的默认体验是轻整理。倾向于**补一个可选的「轻整理」档**
（先做确定性规则版：去口癖、断句、标点规整，不上 LLM），默认关，让用户选——这是砍掉旧 polish 模式之后留下的
真实空档。

## 4. 不建议做的

- **不要再加第四个模式**。现在的方向应该是减，不是加。
- 不要做云账户/同步——和 local-first 定位正面冲突。
- 不要在卡片里内嵌播放器/编辑器（用 `open_file` 交给系统应用的决定是对的，别反悔）。
- **不要在 P0 之前先做流式**。流式让「慢」变得好看，词典让「错」消失。后者价值高一个量级。

也是后面每一条建议应该遵循的同一个原则。
